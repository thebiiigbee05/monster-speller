## 11.1 เกณฑ์ความสำเร็จของโครงการ (KPIs)

| ด้าน | ตัวชี้วัด | เป้าหมาย |
|---|---|---|
| **ผลสัมฤทธิ์การสะกดคำ** | คะแนน Post-test > Pre-test | นัยสำคัญทางสถิติ (p < .05) + Effect size ≥ 0.5 |
| **ความแม่นยำจำแนกมาตรา** | อัตรายิงถูกในเกม (ด่านสุดท้าย) | ≥ 75% (ไม่ใช้คำใบ้ระดับ 3–4) |
| **แรงจูงใจ** | คะแนน IMMS (ARCS) | เฉลี่ย ≥ 3.5/5 |
| **ความพึงพอใจ** | แบบสอบถาม | เฉลี่ย ≥ 4.0/5 |
| **การใช้งาน** | ผู้เรียนเล่นครบ 8 ด่าน / เล่น ≥ 5 รอบ | ≥ 80% ของกลุ่มตัวอย่าง |
| **ประสิทธิภาพทางเทคนิค** | FPS ≥ 45 บน Min Spec, ไม่มี Critical bug | ผ่านเกณฑ์บทที่ 8.4 / 10.6 |
| **การจัดการโครงการ** | Sprint Goal สำเร็จ, Cycle Time | ≥ 80% ตามแผน, Cycle Time < 3 วัน |

## 11.2 แบบแผนการประเมินผลทางการศึกษา

**แบบแผนหลัก (Quasi-Experimental):**

```
กลุ่มทดลอง   O₁  →  X  →  O₂
O₁ = Pre-test (มาตราตัวสะกด 20 ข้อ) · X = เรียนด้วยเกม Monster Speller 8 ด่าน · O₂ = Post-test
(+ IMMS และแบบสอบถามความพึงพอใจหลังเรียน)
```

**แบบแผนเสริม:** กลุ่มควบคุม (สอนแบบปกติ/ใบงาน) เทียบกลุ่มทดลอง — Non-equivalent control group design

**การควบคุมตัวแปรแทรกซ้อน:** ครูคนเดียวกัน, แบบทดสอบคู่ขนาน A/B สลับ, เวลาเรียนเท่ากัน, กลุ่มทดลองเล่นคนละเครื่อง/คาบเรียนเดียวกัน

## 11.3 สถิติและการวิเคราะห์ข้อมูล

| ข้อมูล | การวิเคราะห์ | สถิติ |
|---|---|---|
| คะแนน Pre/Post (กลุ่มเดียว) | เปรียบเทียบก่อน–หลัง | Paired t-test (Wilcoxon ถ้าไม่ปกติ) |
| 2 กลุ่ม (ทดลอง/ควบคุม) | เปรียบเทียบผล | Independent t-test / ANCOVA (ควบคุม Pre-test) |
| ขนาดผล | ขนาดความแตกต่าง | Cohen's d |
| ความแม่นยำในเกมรายมาตรา | ร้อยละถูก/ผิดต่อมาตรา | Descriptive + Misconception Map |
| แรงจูงใจ/ความพึงพอใจ | ค่าเฉลี่ย, SD, ร้อยละ | Descriptive |
| ความเชื่อมั่นแบบสอบถาม | ความสอดคล้องภายใน | Cronbach's Alpha ≥ 0.70 |
| ข้อมูลเชิงคุณภาพ (สัมภาษณ์) | วิเคราะห์เนื้อหา | Thematic Analysis |

**เครื่องมือ:** Jamovi / JASP / SPSS / Python (SciPy)

## 11.4 การวิเคราะห์ความเสี่ยง

| # | ความเสี่ยง | โอกาส | ผลกระทบ | มาตรการรับมือ |
|---|---|---|---|---|
| R1 | มาตรา/เฉลยผิดหลักภาษาไทย (เช่น ตรวจคำผิด) | ต่ำ | สูง | ครูภาษาไทยตรวจ IOC ทุกคำ + ทดสอบอัตโนมัติรายมาตรา (บทที่ 10.2) |
| R2 | Canvas ช้า/กระตุกบนคอมพิวเตอร์โรงเรียนรุ่นเก่า | กลาง | กลาง | Tech Spike Sprint 0, Sprite atlas เดียว, โหมดลดเอฟเฟกต์, Min Spec ชัดเจน |
| R3 | แป้น 1–8 ไม่ทำงานเมื่อเปิด IME ไทย | กลาง | กลาง | ใช้ `event.code`, ทดสอบข้ามเบราว์เซอร์/IME |
| R4 | AR สแกนการ์ดไม่ขึ้น (แสง/กล้อง) | สูง | ต่ำ | แจ้งเงื่อนไขแสง, การ์ด contrast สูง, Fallback โหมดจอปกติ |
| R5 | นักเรียนเดาสุ่มยิง ไม่เกิดการเรียนรู้ | กลาง | กลาง | ผลป้อนกลับบังคับอธิบาย, คำใบ้ค่อยเป็นค่อยไป, วิเคราะห์ความแม่นยำรายมาตรา |
| R6 | ธนาคารคำศัพท์ไม่เพียงพอ/ซ้ำ | กลาง | กลาง | เตรียม 200+ คำ, ตรวจสอบโดยครู, เพิ่มคำตามฟีดแบ็ก Pilot |
| R7 | การเปลี่ยนแปลงความต้องการระหว่างพัฒนา | สูง | กลาง | Backlog Refinement รายสัปดาห์, PO ตัดสินใจเร็ว |
| R8 | ความเป็นส่วนตัว/สิทธิ์กล้อง (PDPA) | ต่ำ | สูง | ประมวลผลในเครื่อง, ไม่เก็บข้อมูลระบุตัวตน, ยินยอมผู้ปกครอง |
| R9 | อินเทอร์เน็ตโรงเรียนไม่เสถียร | สูง | ต่ำ | PWA + offline cache, assets เบา |

## 11.5 แผนสำรอง (Contingency Plan)

| สถานการณ์ | แผนสำรอง |
|---|---|
| Tech Spike Canvas/AR ล้มเหลว | สลับ: เกมบน DOM+CSS เกม (ง่ายกว่า), AR → ภาพการ์ดเสมือน/ไม่บังคับ |
| Pilot ไม่ถึงเกณฑ์ | วิเคราะห์สาเหตุ → ปรับการออกแบบ (บทที่ 4–5) → ทดลองซ้ำ 1 รอบ |
| ทีมขาดกำลังคน | ตัดฟีเจอร์ Should/Could, ขยายเวลา 2 สัปดาห์ (สำรองในแผน) |
| ครูไม่สะดวกใช้เทคโนโลยี | อบรม + คู่มือ + วีดิทัศน์แนะนำ 5 นาที + ใบงานสำรอง (แบบกระดาษ) |
| บริบทห้องเรียนเปลี่ยน (เรียนออนไลน์) | เกมเป็น PWA เล่นที่บ้านได้ + โหมดคนเดียวสมบูรณ์ |

> 🔗 **เชื่อมโยง:** เครื่องมือวัด → บทที่ 5 · แผน Pilot → บทที่ 10.5 · ติดตามความเสี่ยงผ่าน Kanban → บทที่ 9
