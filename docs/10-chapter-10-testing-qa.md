## 10.1 กลยุทธ์การทดสอบ (Test Pyramid)

```
          /\   E2E (Playwright) — เส้นทางหลัก: เลือกด่าน → เล่น 3 นาที → สรุป
         /  \  2–3%
        /----\
       /  Integration  \  GameEngine ↔ Pinia store ↔ Canvas (10%)
      /----------------\
     /  Unit (Vitest)     \  ตรวจมาตรา, คะแนน, Monster class, stores (มากที่สุด)
    /----------------------\
```

**หลักการ:** ทดสอบแต่เนิ่น ๆ ทุก Pull Request ผ่าน CI (typecheck + unit + lint); การทดสอบเป็นส่วนหนึ่งของ DoD (บทที่ 8.3); งานที่ทดสอบยาก (AR) → แยกตรรกะเป็นฟังก์ชันบริสุทธิ์ + ทดสอบด้วยมือ

## 10.2 การทดสอบระดับหน่วยและบูรณาการ

| ระบบ | ตัวอย่างการทดสอบ |
|---|---|
| ตรวจมาตรา (Matra checker) | คำ "เลข" → ต้องได้แม่กก (ไม่ตรงมาตรา); "มาก" → แม่กก (ตรง); "ตา" → แม่กา |
| กระสุน 1–8 | กด 1 → เลือก "กา" … กด 8 → "เกอว"; กดซ้ำ/ค้างไม่พัง |
| คลาส Monster | HP ลดเมื่อถูกยิง; ถูกต้อง → state 'friendly'; ผิด → 'stunned' + คำใบ้; BossMonster ต้องยิงหลายคำติด |
| คะแนน/ตัวคูณ | ถูกติดต่อเพิ่มตัวคูณ; ผิดรีเซ็ต; คะแนนสรุปรอบถูกต้อง |
| คำใบ้ (ระดับ 1–4) | ผิดครั้งที่ 1 → ชะงัก; ครั้งที่ 2 → คำใบ้แดง; … ระดับ 4 (โหมดผ่อนปรน) เฉลยเต็ม |
| Pinia stores | GameState รีเซ็ตเมื่อเริ่มรอบใหม่; Hall of Fame เก็บ 10 อันดับสูงสุด; Settings บันทึกถาวร |
| ชิ้นส่วนอัปเกรด | ครบเกณฑ์ → ปลดล็อกชิ้นส่วน; เอฟเฟกต์ (ปืนคู่/โล่) ทำงานจริง |
| ธนาคารคำ | ทุกคำมีมาตรา/ตัวสะกดถูกต้องตามชุดข้อมูล; ไม่ซ้ำในรอบ |

**เครื่องมือ:** Vitest (unit) · Playwright (E2E) · GitHub Actions (CI)

## 10.3 การทดสอบข้ามอุปกรณ์ (Device Matrix)

| อุปกรณ์ | เบราว์เซอร์ | จุดทดสอบหลัก |
|---|---|---|
| คอมพิวเตอร์โรงเรียน | Chrome/Edge | เมาส์เล็ง/ยิง, แป้น 1–8 (IME ไทย), 60fps |
| แท็บเล็ต Android/iPad | Chrome/Safari | Touch (ปุ่มกระสุน), จอหมุน, ประสิทธิภาพ Canvas |
| สมาร์ตโฟน | Chrome/Safari | UI ย่อ, Touch, โหมด AR |
| คอมพิวเตอร์รุ่นเก่า | Chrome | Canvas ประหยัดทรัพยากร (Min Spec) |

**กรณีทดสอบข้ามเงื่อนไข:**
- ปิดเสียง → คำใบ้/เฉลยยังเห็นเป็นข้อความ
- เปิด IME ภาษาไทย → แป้น 1–8 ยังเลือกกระสุนได้
- ปฏิเสธสิทธิ์กล้อง/ไม่มีกล้อง → โหมด AR ซ่อน, โหมดจอปกติทำงาน
- ออฟไลน์หลังโหลดครั้งแรก → PWA เล่นได้
- ความเร็วช้า/ปกติ/เร็ว → ความเร็วมอนสเตอร์เปลี่ยนตามจริง
- จบรอบ 3 นาที → ระบบสรุป/บันทึกผลถูกต้อง

## 10.4 การทดสอบการใช้งานกับผู้ใช้จริง (Usability Testing)

**รูปแบบ:** นักเรียนกลุ่มเป้าหมาย 5–10 คน/รอบ (กฎ Nielsen)

| ขั้นตอน | รายละเอียด |
|---|---|
| 1. เตรียมงาน | เลือกด่าน 1–2, บันทึกวิดีโอ (ยินยอม), แบบสังเกต |
| 2. ให้ผู้เรียนเล่น | เล่นเองตามธรรมชาติ — ผู้สังเกตไม่ชี้นำ |
| 3. เก็บข้อมูล | เวลาสำเร็จ, จุดติดขัด, ความสับสน (Think-aloud) |
| 4. สัมภาษณ์สั้น | "สนุกตรงไหน / งงตรงไหน / อยากได้อะไรเพิ่ม" |
| 5. สรุป | จัด Severity → การ์ดปรับปรุง → Kanban |

**ตัวชี้วัด:** Task Success ≥ 80%, ผู้เรียนเล่นจบรอบโดยไม่ขอความช่วยเหลือ, อัตรายิงผิดโดยไม่ใช้คำใบ้ลดลง

## 10.5 การทดสอบประสิทธิผลทางการศึกษา (Pilot)

ก่อนใช้งานจริง (Sprint 7) ต้องผ่าน **การทดลองนำร่อง**:

| รายการ | ข้อกำหนด |
|---|---|
| กลุ่มตัวอย่าง | นักเรียน ป.3–4 อย่างน้อย 2 ห้องเรียน (ประมาณ 60–80 คน) |
| แบบแผน | One-group Pre-test / Post-test (+ กลุ่มควบคุมถ้าเป็นไปได้) |
| ระยะเวลา | 1–2 สัปดาห์ ตามแผนการจัดการเรียนรู้ (บทที่ 5) |
| เครื่องมือวัด | แบบทดสอบคู่ขนาน (บทที่ 5.3), IMMS (บทที่ 5.5), การสังเกต |
| เกณฑ์ตัดสิน | คะแนนหลังเรียนสูงกว่าก่อนเรียนอย่างมีนัยสำคัญ (p < .05) + ความพึงพอใจ ≥ ระดับดี |

> รายละเอียดการวิเคราะห์ทางสถิติ → บทที่ 11

## 10.6 ระบบติดตามข้อบกพร่อง (Bug Tracking)

**บั๊กทุกตัว = การ์ดบนบอร์ด Kanban (หมวด 🐛):**

```
🐛 [BUG-014] ด่าน 4: ยิงถูกแม่กบ แต่ระบบนับเป็น "ผิด" (คำว่า "ภาพ")
📱 อุปกรณ์: Chrome 120, Windows 11
🔁 วิธีทำซ้ำ: ด่าน 4 → มอนสเตอร์ถือคำ "ภาพ" → ยิงกระสุน กบ → นับผิด + คำใบ้
✅ พฤติกรรมที่ควรเกิด: "ภาพ" (พ = แม่กบ ไม่ตรงมาตรา) ต้องนับถูก
🔴 Severity: สูง (High) — เนื้อหาผิดพลาด
🚩 สถานะ: In Progress → QA → Done
```

**ระดับ Severity:**

| ระดับ | นิยาม | SLA |
|---|---|---|
| 🔴 Critical | เกมเล่นไม่ได้ / ข้อมูลสูญหาย / **มาตราเฉลยผิดหลักภาษาไทย** | แก้ภายใน 24 ชม. |
| 🟠 High | ฟีเจอร์หลักใช้งานไม่ได้บางกรณี | แก้ใน Sprint ปัจจุบัน |
| 🟡 Medium | ทำงานได้แต่ UX ผิดพลาด | จัดลำดับใน Backlog |
| 🟢 Low | ความสวยงาม/ข้อความสะกด | จัดรวมรอบแก้ |

**มาตรฐานก่อน Release:** Critical = 0 · High ≤ 3 (มีแผนแก้) · E2E เส้นทางหลัก 100% · Pilot ผ่านเกณฑ์ (10.5)

> 🔗 **เชื่อมโยง:** QA ติดตามผ่านบอร์ด Kanban (บทที่ 9) และ DoD (บทที่ 8.3)
