## 8.3 Definition of Done (DoD) — ทุก User Story ต้องผ่าน

- [ ] โค้ด Vue3 + TypeScript ผ่าน typecheck + lint
- [ ] **ทุกไฟล์โค้ดมีความยาวไม่เกิน 800 บรรทัด** (แตกโมดูล/คลาส/คอมโพเนนต์เมื่อใกล้ถึงขีดจำกัด — ดู 8.6)
- [ ] ผ่าน Unit Test (Vitest) — ครอบคลุม logic (คะแนน, ตรวจมาตรา, Pinia store)
- [ ] ผ่านการทดสอบด้วยมือบนอุปกรณ์เป้าหมาย (คอม/แท็บเล็ต)
- [ ] Content Specialist ตรวจคำศัพท์/มาตรา/คำใบ้ถูกต้อง
- [ ] ไม่มีข้อผิดพลาดในคอนโซล; เกม loop ≥ 45fps บน Min Spec
- [ ] Code Review ผ่าน ≥ 1 คน
- [ ] อัปเดตเอกสารที่เกี่ยวข้อง

## 8.4 เกณฑ์การยอมรับ (Acceptance Criteria) — ตัวอย่าง US-02

> "เลือกกระสุนมาตราด้วยแป้น 1–8"

1. กด 1–8 → ปุ่มกระสุนมาตรา (1=กา … 8=เกอว) เปลี่ยนสถานะ "เลือก" ทันที + HUD อัปเดต
2. ทำงานแม้เปิด IME ภาษาไทย (ใช้ `event.code` Digit1–Digit8)
3. คลิกที่ปุ่มกระสุนก็เลือกได้เช่นกัน (เมาส์/แตะ)
4. ยิงด้วยกระสุนที่เลือก → ตรวจมาตรากับคำของมอนสเตอร์ถูกต้อง (ถูก/ผิด/ชะงัก)
5. กระสุน 8 ชนิดมีสี/ป้ายกำกับมาตราเห็นชัด (บทที่ 6.4)

## 8.6 ข้อตกลงการเขียนโค้ด (Coding Convention)

> ข้อตกลงร่วมของทีม — ทุกไฟล์โค้ด (TypeScript/Vue/HTML/CSS ที่เป็นโค้ด) ต้องเป็นไปตามกฎนี้

| ข้อตกลง | รายละเอียด |
|---|---|
| **ความยาวไฟล์สูงสุด** | แต่ละไฟล์โค้ดต้อง **ไม่เกิน 800 บรรทัด** — ใกล้ถึงขีดจำกัดให้แตกโมดูล/คลาส/คอมโพเนนต์ย่อยทันที เช่น `Monster.ts` → `game/monsters/WalkerMonster.ts`, `RunnerMonster.ts`, … ; `GameEngine.ts` → แตก `input/`, `renderer/`, `wave/` |
| **หลัก Single Responsibility** | 1 ไฟล์ = 1 ความรับผิดชอบหลัก — ห้ามรวม GameEngine + UI + logic ไว้ไฟล์เดียว |
| **Vue Components เล็ก** | คอมโพเนนต์ที่ยาวเกิน 800 บรรทัด → แตกเป็นคอมโพเนนต์ลูก (เช่น `SettingsModal` → `SettingsModalAudio`, `SettingsModalSpeed`) |
| **ไฟล์ข้อมูล** | `wordBank.json`/`levelConfig.ts` เป็นไฟล์ข้อมูล ไม่นับโค้ดลอจิก — แต่ยังคงจัดระเบียบต่อมาตรา/ต่อด่าน |
| **การบังคับใช้** | ตรวจสอบอัตโนมัติใน CI (สคริปต์นับบรรทัด, ขีดจำกัด = 800) + ตรวจใน Code Review (DoD 8.3) |
